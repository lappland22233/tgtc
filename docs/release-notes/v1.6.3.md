# TGTC v1.6.3 发布说明

本维护版修复认证、分享预览、账号池文件复制和 IP 解封的一致性问题，改进严格小盘模式下的批量上传排队与异常恢复，治理生产依赖高危漏洞，并补齐真实数据库回归与本地/CI 共用质量门禁。本版本没有新增数据库迁移。

## 修复与改进

- **严格小盘模式下的上传排队**：未设置 `STRICT_UPLOAD_SINGLE_PROCESS` 时默认启用；该模式仅在单个后端进程且 `FILE_CACHE_NO_CACHE_MODE=true` 时生效。批量上传按单文件依次占用服务端上传通道，后续文件显示排队状态，并按服务端给出的间隔重试。
- **上传中断恢复**：异常中断时释放上传通道，避免后续文件永久等待；修复批量上传期间把排队误报为磁盘空间不足的问题。
- **认证与分享一致性**：验证码匹配及消费前原子执行限流，锁定期间不能继续猜测密码重置；告警 WebSocket 在连接建立及生命周期复核时复用 HTTP 会话验证，检查 JWT 吊销、密码修改和用户状态；分享预览会话确认与额度扣减在同一事务中完成，兼容 SQLite/PostgreSQL，最后一次访问名额内的同会话 Range/重连可继续，新访客仍被拒绝。
- **文件复制与解封**：文件复制保留来源 Bot、内容稳定身份及消息锚点，并为新逻辑文件复制每个账号已有的 ready 副本，避免用默认 Bot 下载其他账号的 `file_id`。分享和文件密码校验尊重管理员解封，自动再次封禁会重新激活封禁记录。
- **后端依赖安全（SEC-101B）**：升级 `multer` 至 `2.5.0`，修复 `GHSA-q7qp-rjg7-q26m`（请求中断后异步 fileFilter 导致未捕获异常引发 DoS）；修复 express 内部传递依赖 `proxy-addr`（CVE-2024-52316 / `GHSA-jqcg-44mw-7w3h`，Critical 级 IPv4-mapped IPv6 受信任子网伪造绕过）、`body-parser`（`GHSA-27r3-jxmh-p828` 压缩请求体后 DoS）、`sharp`（`GHSA-wq5f-xc86-pv6w` librsvg CVE-2026-96889）、`undici`（`GHSA-4qv8-2p9j-2685` 等 5 条高危 DoS 与 TLS 绕过）及 `follow-redirects`（`GHSA-q3jh-wrc6-jgq8` 等凭据泄露绕过）。生产依赖高危门禁 `npm audit --omit=dev --audit-level=high` 无漏洞，不添加审计忽略项。
- **前端 XSS 修复（SEC-101F）**：升级 `vue` 至 `3.5.44`，修复 `@vue/server-renderer` 的 `GHSA-g2v6-rqmx-r4w6` 属性黑名单遗漏 CR 导致的 XSS 漏洞；前端生产依赖高危审计结果为零漏洞。
- **死代码与审查基线（OD-101）**：经全仓引用分析移除 3 个业务零引用的 Composable：`useDragMove.ts`、`useFileClipboard.ts`、`useTimeRange.ts`。完成覆盖服务端性能、客户端性能、安全性、用户体验、运维难度、文档可读性与过度设计的全量审查，记录于 `.codebuddy/review-report-v1.6.2.md`。
- **回归与质量门禁**：SQLite/PostgreSQL 共用业务回归覆盖并发、事务回滚、限次预览、吊销、解封和复制下载；增加真实 Redis 任务生命周期与 HTTP multipart 单文件、多文件、超限和中断清理测试。前后端增加 `npm run check:ci` 并由 CI 调用，统一依赖树、审计、类型、构建和覆盖率检查；前端增加覆盖率下限并保留原有体积门禁。

## 数据库、回退与兼容性

- 没有新增数据库迁移，继续兼容现有 PostgreSQL/SQLite 结构和 API；VERSION、前后端清单及两份锁文件统一为 1.6.3。
- 发行包仍包含完整迁移链，`RELEASE_INCLUDES_DB_MIGRATION=true`。`RELEASE_ROLLBACK_SAFE=false`：迁移链含历史不可逆回填，回退前须按运维文档恢复数据库备份；回退安全修复会重新暴露旧漏洞。
- 目标平台为 Linux x86_64，运行时支持 SQLite 默认配置和 PostgreSQL。1.6.0 及以上版本可升级，客户端无需变更，API 与前端资源保持向后兼容。
