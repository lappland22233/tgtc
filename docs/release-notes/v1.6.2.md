# TGTC v1.6.2 发布说明

本版本为**维护版**：不引入新功能、不新增数据库迁移，聚焦发布可靠性、镜像内容完整性与安全/E2E 验证缺口。

## 1.6.2 修复

- **镜像回退源只接受可证明属于当前文件版本的副本**：站内文件的源定位回退改为按当前 `telegramFileUniqueId` 精确查询候选副本，并用已知文件大小交叉校验。**同尺寸但身份不同**、**缺少稳定身份（`file_unique_id`）**、**锚点缺失**或**大小不匹配**的副本都不再被用于回退，一律以 `source_copy_identity_unresolved` 阻塞，而不是拿无法验证的旧副本继续扩散。
- **回退来源账号必须当前可执行**：账号池生效时，只从池运行快照中「已启用且配置了存储 Chat」的账号里挑选源副本；池内没有可用账号时保守阻断，不再回落到可能已停用/移除的旧账号记录。池未生效时保持既有单账号路径行为。
- **镜像任务执行以源解析结果为准**：中继使用的来源账号取源解析事实（回退副本的持有账号），仅当源描述未给出账号时才回落到任务行快照，避免历史任务里过期的 `sourceAccountId` 把 A 账号的消息交给 B 账号取用。
- **恢复安全 HTTP E2E 覆盖**（此前被跳过）：访问日志凭据脱敏、分享密码验证的 Cookie 安全属性（HttpOnly / SameSite=Lax / 受限 Path）、危险 MIME（SVG）在公开媒体直链被拒绝、媒体响应安全头（nosniff / no-referrer / 限制性 CSP / no-store）由现有流水线实际执行。
- **前端管理台修复**：副本扩散「事件区」按状态筛选时，在结果返回前切回「全部」不再让列表停留在「筛选结果加载中」；配合请求代次判定，晚到的旧响应不会覆盖新筛选结果。
- **版本守卫强化**：`check-version.sh` 现在同时校验 lockfile 的**顶层 `version`** 与 **`packages[""].version`** 两处根包版本（此前只校验后者，手工升版本时可能出现半改状态）；新增 `scripts/release/tests/check-version.test.sh` 锁定一致放行、任一字段不一致/缺失、非 SemVer 与 tag/`CI_TAG` 守卫共 10 个用例。
- **发行构建对缺失发布说明 fail-closed**：`build-linux-x64-release.sh` 在构建早期即检查 `docs/release-notes/v<版本>.md` 是否存在，缺失时拒绝生成发行材料（此前仅告警，可能产出无版本说明的制品）。

## 随本版本一并发布（原计划 1.6.1，未单独发布）

- **下载期受控懒触发补扩散**：站内下载冷路径发现 ready 副本数低于有效目标时，补建一次镜像任务（15 分钟进程内冷却 + 同步占位收敛并发；只建单、零字节；不重开 `failed`/`blocked` 终态；源锚点不可定位时不建单；异常一律 fail-open 不影响下载）。下载路径本身仍不搬字节，扩散仍只由镜像任务队列执行。
- **源锚点旧版本误用修复**：异常回退不再跨账号借用 `file_id`，并在副本大小与当前文件不一致时按旧版本残留处理。
- **管理台可观测性**：扩散轮次时间线窗口与整表筛选（失败/认领超时/可重试）、审计降级如实提示；新增批量上传示例脚本。

## 数据库与回退

- **无新增迁移**：本版本仅为代码、测试与文档变更，继续兼容 180330–180390（PG/SQLite）已落地的结构，不删改旧字段与旧路径。
- 发行包仍携带**完整迁移链**，因此 `RELEASE_INCLUDES_DB_MIGRATION=true`：从更旧版本升级到本版本仍需执行迁移，**升级前必须备份数据库**。
- `RELEASE_ROLLBACK_SAFE=false`：仅切回旧代码并不安全（迁移链仍含不可逆回填：1.2.7 的 180200 与 1.6.0 的 180380）。`rollback.sh` 会拒绝自动回退，需按运维文档确认数据库已恢复到备份快照后显式放行。
- 本版本尚未执行真实升级/回滚演练；正式升级前请在隔离环境完成一次 PostgreSQL/SQLite 升级与备份恢复演练。

## 兼容性

- 目标平台：Linux x86_64；运行时 SQLite 默认 / PostgreSQL 双方言。
- 升级路径：1.6.0（当前稳定版）以及支持自动升级的更早版本，均可按清单的 `minUpgradableVersion` / `maxUpgradableVersion` 判断是否走自动升级。
- 客户端无需变更：前端资源与后端 API 路径保持向后兼容。
